Større enn én nettside

Webplattformen

HTML og CSS er deler av et større sett med standarder og mekanismer som utgjør World Wide Web. Her er målet å plassere dem i helheten, ikke å gjøre modulen til et nettverkskapittel.

HTTP
Kommunikasjon mellom klienter og tjenester på web.
URI / URL
Identifiserer og adresserer ressurser.
DNS
Knytter domenenavn til tjenestene nettleseren skal nå.
MIME types
Beskriver hvilken type innhold som sendes.
HTML
Beskriver dokumentets struktur og mening.
CSS
Styrer presentasjon og layout.
ECMAScript / JavaScript
Gir webapplikasjonen dynamisk oppførsel.

Struktur og mening

HTML

HTML står for HyperText Markup Language og er dokumentformatet for websider.

Et HTML-dokument består av standardiserte elementer og attributter. Elementene beskriver hva innholdet er og hvordan dokumentet er strukturert.

<!DOCTYPE html>
<html lang="no">
<head>
    <meta charset="UTF-8">
    <title>Min side</title>
</head>
<body>
    <h1>Webutvikling</h1>
    <p>Dette er innholdet på siden.</p>
</body>
</html>

Dokument

html · head · body

Tekst og lenker

h1–h6 · p · a

Media og samlinger

img · ul · ol · li · table

Sideområder

header · nav · main · section · article · footer

Dette er et utvalg for å forstå struktur og mening, ikke en full HTML-reference.

Elementer og attributter

Et element angir hvilken type innhold vi har. Et attribute gir informasjon om elementet. Content er innholdet elementet omslutter eller representerer.

<p class="intro">Dette er innholdet.</p>
Element
p
Attribute
class="intro"
Content
Dette er innholdet.
<img src="campus.jpg" alt="Studenter utenfor campus">

alt-attributtet beskriver bildet når selve bildet ikke kan oppfattes eller lastes. Andre vanlige attributter er id, class, style, lang, dir, role, tabindex og aria-*.

Mening før presentasjon

Semantikk og tilgjengelighet

Semantisk HTML

Semantisk markup betyr at HTML-elementet kommuniserer hvilken type informasjon eller struktur det representerer, uavhengig av hvordan det ser ut.

Generisk struktur

Gir et navn, men lite innebygd mening

<div class="navigation">
    ...
</div>

Bedre når innholdet er navigasjon

Elementet uttrykker rollen direkte

<nav>
    ...
</nav>

header, nav, main, section, article, footer og button gir struktur med mening. div er fortsatt riktig når det ikke finnes et passende semantisk element; problemet er ukritisk bruk av generiske elementer.

Tilgjengelighet / Accessibility

Informasjon og funksjoner på web skal kunne brukes uavhengig av funksjonsevne. God bruk av HTML er fundamentet for accessibility.

  • Bruk en tydelig heading structure.
  • Bruk lenker til navigasjon og native buttons til handlinger.
  • Koble form controls til tydelige labels.
  • Skriv meaningful text labels og text alternatives for images.
  • Bruk ARIA når native HTML ikke er nok, ikke som førstevalg.

Native HTML

<button>Lagre</button>

Har riktig grunnlag for semantikk, fokus og tastaturinteraksjon.

Generisk element

<div class="button">Lagre</div>

Ser kanskje lik ut, men mangler knappens innebygde betydning og oppførsel.

Native first: Det er normalt bedre å velge riktig HTML-element enn å bygge interaksjon av en div og reparere semantikken manuelt.

WCAG gir retningslinjer for tilgjengelig webinnhold, og Google Lighthouse kan støtte evaluering. Detaljerte kriterier kommer senere; her er hovedpoenget at tilgjengelighet begynner i strukturen.

Presentasjon og kobling

CSS og selectors

CSS står for Cascading Style Sheets og brukes til presentasjon og layout.

CSS kan styre blant annet typography, size, margins, spacing, colors og layout. En regel består av en selector og én eller flere deklarasjoner med property og value.

selector {
    property: value;
}

h1 {
    font-size: 2rem;
}

Element selector

h1 {
    font-size: 2rem;
}

Bruker elementnavnet.

Class selector

.card {
    padding: 1rem;
}

Starter med .

ID selector

#main-content {
    max-width: 1200px;
}

Starter med #

Mer avanserte selector-uttrykk finnes, men denne modulen etablerer bare grunnformen.

Moderne layout

Flexbox og Grid

Hovedforskjellen ligger i hvor mange dimensjoner layouten organiserer samtidig.

Flexbox · primært 1D

Row eller column

ABC
.wrapper {
    display: flex;
    flex-wrap: wrap;
}

Grid · 2D

Rows og columns

ABCDEF
.wrapper {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
}
Parent/container-prinsippet: Layoutreglene settes på containeren og bestemmer hvordan child-elementene organiseres.

Én løsning · flere enheter

Responsivt webdesign

Responsive web design er webdesign der siden eller applikasjonen tilpasser seg størrelsen på skjermen og enheten den vises på. Målet er at løsningen skal se bra ut og være enkel å bruke uansett enhet.

Responsive design
  • flexible layout
  • viewport
  • media queries
  • responsive images
  • breakpoints

Mekanismene

Viewport, media queries og bilder

Viewport

Viewport er brukerens synlige del av siden eller skjermen.

<meta name="viewport"
      content="width=device-width, initial-scale=1.0">

width=device-width setter viewport-bredden i forhold til enhetens skjermbredde. initial-scale=1.0 angir opprinnelig zoomnivå.

CSS har også viewport-relative units: vh, vw, vmin og vmax.

.hero {
    min-height: 100vh;
}

Media queries

Media queries lar CSS-regler avhenge av betingelser som skjermstørrelse.

article {
    display: flex;
    flex-direction: row;
}

@media screen and (max-width: 600px) {
    article {
        flex-direction: column;
    }
}

Media queries kan blant annet endre layout, font size, component size og colors.

Breakpoints

Et breakpoint er en skjermstørrelse der layouten tilpasses eller endrer struktur. En desktop-layout med sidebar og main content kan for eksempel bli til kompakt hamburger navigation og main content på mobil.

  • Flere columns kan bli til én column.
  • En rad kan vise færre items.
  • Navigation kan få en annen form.
Viktig: Responsivt design handler ikke bare om å krympe innhold. Layouten kan organiseres annerledes.

Responsive bilder

<img
    src="image.jpg"
    alt="..."
    style="max-width: 100%; height: auto;"
>

max-width: 100% gjør at bildet kan tilpasse seg tilgjengelig plass, mens height: auto bevarer proporsjonene.

<picture>
    <source srcset="small.jpg" media="(max-width: 600px)">
    <source srcset="large.jpg" media="(max-width: 1500px)">
    <img src="fallback.jpg" alt="...">
</picture>

picture kan velge forskjellige bilder ut fra media conditions.

Metode og forståelse

Mobile-first og rammeverk

Forelesningen introduserer mobile-first som en mulig utviklingsmetode, ikke som et absolutt krav. Metoden starter med den mindre visningen og utvider layouten når mer plass blir tilgjengelig.

Det finnes UI-frameworks og libraries med innebygd støtte for responsive design. I IT2810 er poenget først å forstå mekanismene: Grid, Flexbox, viewport, media queries, responsive images og breakpoints.

Målet er forståelse, ikke et perfekt resultat ved hjelp av flest mulig rammeverk.

Hvordan alt henger sammen

Frontend bygges lagvis, men semantikk og tilgjengelighet må vurderes gjennom hele løsningen.

Fra teori til arbeid

Hvorfor dette betyr noe i Prosjekt 1

Prosjekt 1 skal eksplisitt gi erfaring med responsive web design og accessibility. Senere brukes fundamentet sammen med TypeScript, Node.js, React, Git og testing.

Vanlige fallgruver

  1. Klikkbar divnår button er riktig element.
  2. Mange nested div-eruten semantisk struktur.

  5. Responsivitet som bare krympingi stedet for å endre layout når det er nødvendig.
  6. ARIA som reparasjonnår et passende native element allerede finnes.

Kortversjonen

  • HTML beskriver struktur og mening.
  • Semantic HTML gir informasjon både til mennesker og programvare.
  • CSS bestemmer presentasjon og layout.
  • Flexbox brukes hovedsakelig for én dimensjon.
  • Grid brukes for to dimensjoner.
  • Viewport er brukerens synlige område.
  • Media queries lar styling reagere på skjermforhold.

  • Responsive images tilpasser seg tilgjengelig plass og enhet.
  • Accessibility begynner med god HTML.
  • Responsive design og accessibility bør bygges inn fra starten.
  • Dette er fundamentet for senere React-utvikling.
