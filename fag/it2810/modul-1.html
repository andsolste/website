Større enn én nettside

Webplattformen

HTML og CSS er deler av et større sett med standarder og mekanismer som utgjør World Wide Web. Her er målet å plassere dem i helheten, ikke å gjøre modulen til et nettverkskapittel.

HTTP
Kommunikasjon mellom klienter og tjenester på web.
URI / URL
Identifiserer og adresserer ressurser.
DNS
Knytter domenenavn til tjenestene nettleseren skal nå.
MIME types
Beskriver hvilken type innhold som sendes.
HTML
Beskriver dokumentets struktur og mening.
CSS
Styrer presentasjon og layout.
ECMAScript / JavaScript
Gir webapplikasjonen dynamisk oppførsel.

Struktur og mening

HTML

HTML står for HyperText Markup Language og er dokumentformatet for websider.

Et HTML-dokument består av standardiserte elementer og attributter. Elementene beskriver hva innholdet er og hvordan dokumentet er strukturert.

<!DOCTYPE html>
<html lang="no">
<head>
    <meta charset="UTF-8">
    <title>Min side</title>
</head>
<body>
    <h1>Webutvikling</h1>
    <p>Dette er innholdet på siden.</p>
</body>
</html>

Dokument

html · head · body

Tekst og lenker

h1–h6 · p · a

Media og samlinger

img · ul · ol · li · table

Sideområder

header · nav · main · section · article · footer

Dette er et utvalg for å forstå struktur og mening, ikke en full HTML-reference.

Elementer og attributter

Et element angir hvilken type innhold vi har. Et attribute gir informasjon om elementet. Content er innholdet elementet omslutter eller representerer.

<p class="intro">Dette er innholdet.</p>
Element
p
Attribute
class="intro"
Content
Dette er innholdet.
<img src="campus.jpg" alt="Studenter utenfor campus">

alt-attributtet beskriver bildet når selve bildet ikke kan oppfattes eller lastes. Andre vanlige attributter er id, class, style, lang, dir, role, tabindex og aria-*.

Mening før presentasjon

Semantikk og tilgjengelighet

Semantisk HTML

Semantisk markup betyr at HTML-elementet kommuniserer hvilken type informasjon eller struktur det representerer, uavhengig av hvordan det ser ut.

Generisk struktur

Gir et navn, men lite innebygd mening

<div class="navigation">
    ...
</div>

Bedre når innholdet er navigasjon

Elementet uttrykker rollen direkte

<nav>
    ...
</nav>

header, nav, main, section, article, footer og button gir struktur med mening. div er fortsatt riktig når det ikke finnes et passende semantisk element; problemet er ukritisk bruk av generiske elementer.

Tilgjengelighet / Accessibility

Informasjon og funksjoner på web skal kunne brukes uavhengig av funksjonsevne. God bruk av HTML er fundamentet for accessibility.

  • Bruk en tydelig heading structure.
  • Bruk lenker til navigasjon og native buttons til handlinger.
  • Koble form controls til tydelige labels.
  • Skriv meaningful text labels og text alternatives for images.
  • Bruk ARIA når native HTML ikke er nok, ikke som førstevalg.

Native HTML

<button>Lagre</button>

Har riktig grunnlag for semantikk, fokus og tastaturinteraksjon.

Generisk element

<div class="button">Lagre</div>

Ser kanskje lik ut, men mangler knappens innebygde betydning og oppførsel.

Native first: Det er normalt bedre å velge riktig HTML-element enn å bygge interaksjon av en div og reparere semantikken manuelt.

WCAG gir retningslinjer for tilgjengelig webinnhold, og Google Lighthouse kan støtte evaluering. Detaljerte kriterier kommer senere; her er hovedpoenget at tilgjengelighet begynner i strukturen.

Dynamisk oppførsel

Den samme komponenten går gjennom flere lag. HTML beskriver at elementet er en knapp, CSS bestemmer hvordan den presenteres, og JavaScript kan senere bestemme hva som skjer når brukeren aktiverer den.

HTML

<button class="save-button">Lagre</button>

CSS

.save-button {
    padding: .75rem 1rem;
    font-weight: bold;
}

JavaScript-grunnlaget kommer senere i denne modulen. Her er det nok å forstå ansvarsdelingen.

Presentasjon og kobling

CSS og selectors

CSS står for Cascading Style Sheets og brukes til presentasjon og layout.

CSS kan styre blant annet typography, size, margins, spacing, colors og layout. En regel består av en selector og én eller flere deklarasjoner med property og value.

selector {
    property: value;
}

h1 {
    font-size: 2rem;
}

Element selector

h1 {
    font-size: 2rem;
}

Bruker elementnavnet.

Class selector

.card {
    padding: 1rem;
}

Starter med .

ID selector

#main-content {
    max-width: 1200px;
}

Starter med #

Mer avanserte selector-uttrykk finnes, men denne modulen etablerer bare grunnformen.

Moderne layout

Flexbox og Grid

Hovedforskjellen ligger i hvor mange dimensjoner layouten organiserer samtidig.

Flexbox · primært 1D

Row eller column

ABC
.wrapper {
    display: flex;
    flex-wrap: wrap;
}

Grid · 2D

Rows og columns

ABCDEF
.wrapper {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
}
Parent/container-prinsippet: Layoutreglene settes på containeren og bestemmer hvordan child-elementene organiseres.

Én løsning · flere enheter

Responsivt webdesign

Responsive web design er webdesign der siden eller applikasjonen tilpasser seg størrelsen på skjermen og enheten den vises på. Målet er at løsningen skal se bra ut og være enkel å bruke uansett enhet.

Responsive design
  • flexible layout
  • viewport
  • media queries
  • responsive images
  • breakpoints

Mekanismene

Viewport, media queries og bilder

Viewport

Viewport er brukerens synlige del av siden eller skjermen.

<meta name="viewport"
      content="width=device-width, initial-scale=1.0">

width=device-width setter viewport-bredden i forhold til enhetens skjermbredde. initial-scale=1.0 angir opprinnelig zoomnivå.

CSS har også viewport-relative units: vh, vw, vmin og vmax.

.hero {
    min-height: 100vh;
}

Media queries

Media queries lar CSS-regler avhenge av betingelser som skjermstørrelse.

article {
    display: flex;
    flex-direction: row;
}

@media screen and (max-width: 600px) {
    article {
        flex-direction: column;
    }
}

Mobil

Media queries kan blant annet endre layout, font size, component size og colors.

Breakpoints

Et breakpoint er en skjermstørrelse der layouten tilpasses eller endrer struktur. En desktop-layout med sidebar og main content kan for eksempel bli til kompakt hamburger navigation og main content på mobil.

  • Flere columns kan bli til én column.
  • En rad kan vise færre items.
  • Navigation kan få en annen form.
Viktig: Responsivt design handler ikke bare om å krympe innhold. Layouten kan organiseres annerledes.

Responsive bilder

<img
    src="image.jpg"
    alt="..."
    style="max-width: 100%; height: auto;"
>

max-width: 100% gjør at bildet kan tilpasse seg tilgjengelig plass, mens height: auto bevarer proporsjonene.

<picture>
    <source srcset="small.jpg" media="(max-width: 600px)">
    <source srcset="large.jpg" media="(max-width: 1500px)">
    <img src="fallback.jpg" alt="...">
</picture>

picture kan velge forskjellige bilder ut fra media conditions.

Metode og forståelse

Mobile-first og rammeverk

Forelesningen introduserer mobile-first som en mulig utviklingsmetode, ikke som et absolutt krav. Metoden starter med den mindre visningen og utvider layouten når mer plass blir tilgjengelig.

Det finnes UI-frameworks og libraries med innebygd støtte for responsive design. I IT2810 er poenget først å forstå mekanismene: Grid, Flexbox, viewport, media queries, responsive images og breakpoints.

Målet er forståelse, ikke et perfekt resultat ved hjelp av flest mulig rammeverk.

Hovedmodellen

Hvordan webgrunnlaget henger sammen

Frontend bygges lagvis, men semantikk og tilgjengelighet må vurderes gjennom hele løsningen.

Del B · Programmeringsgrunnlaget

JavaScript og TypeScript essentials

Målet er ikke å dekke hele språkene. Du skal forstå nok til å lese moderne frontendkode, følge dataflyten og oppdage når du må slå opp en detalj.

JavaScript: språk og kjøremiljø

JavaScript gir webapplikasjonen dynamisk oppførsel. Språket må skilles fra miljøet som kjører det.

JavaScript
Programmeringsspråket.
Browser
Et kjøremiljø som kjører webapplikasjonen.
Node.js
Et annet JavaScript-miljø, brukt rundt utviklingsverktøyene i dette faget.
Runtime
Tidspunktet og miljøet der programmet faktisk kjører.

Dynamisk typing

JavaScript er dynamisk typet. Typen følger verdien ved runtime, og samme variabel kan derfor få en verdi av en annen type.

let value = 10;
value = "ti";

Typefeil kan dermed oppstå først når koden kjører. Dette er en viktig grunn til at TypeScript brukes i større frontendprosjekter.

Syntaks du møter hele tiden

Functions og modules

Arrow functions

Arrow functions er en kompakt funksjonssyntaks. Den brukes mye til callbacks, array-metoder, events og senere React-komponenter og handlers.

Vanlig funksjon

function double(x) {
    return x * 2;
}

Arrow function

const double = x => x * 2;

Import og export

Moderne frontendprosjekter består av mange filer og moduler. export gjør noe tilgjengelig fra én modul, mens import henter det inn i en annen.

Eksporter

export const double = x => x * 2;

Importer

import { double } from "./math";

React-komponenter kommer senere til å importeres og eksporteres på samme måte.

Object destructuring

Destructuring henter navngitte felt fra et objekt.

const user = {
    name: "Andreas",
    id: 1
};

const { name, id } = user;

Typekontroll under utvikling

TypeScript essentials

TypeScript er et superset av JavaScript som legger til statisk typekontroll. TypeScript-koden ender som JavaScript før browseren kjører den.

Verdier og funksjoner

const name: string = "Andreas";

function add(a: number, b: number): number {
    return a + b;
}

Objekt og union

interface User {
    name: string;
    id: number;
}

let id: number | string;

Type inference betyr at TypeScript ofte kan finne typen fra verdien uten en eksplisitt annotation. any slår i stor grad av typekontrollen og bør derfor brukes bevisst.

Data gjennom funksjoner

Arrays og deklarativ stil

I moderne frontendkode brukes funksjoner ofte til datatransformasjon. Målet er å kjenne igjen mønstrene, ikke å memorere hele array-API-et.

map()
const doubled = numbers.map(x => x * 2);

Transformer hvert element.

filter()
const even = numbers.filter(x => x % 2 === 0);

Behold elementene som matcher.

find()
Finn første match.
some()
Undersøk om minst én verdi matcher.
every()
Undersøk om alle verdiene matcher.
reduce()
const sum = numbers.reduce((total, x) => total + x, 0);

Kombiner verdier til ett resultat.

Immutability

const numbers = [1, 2, 3];
const doubled = numbers.map(x => x * 2);

numbers endres ikke; doubled er en ny array. I moderne frontendkode unngår man ofte direkte mutasjon og produserer nye verdier når det er naturlig. Dette blir særlig relevant når React-state introduseres i Modul 2.

JavaScript / TypeScript→immutable transformations→React state senere

Deklarativ og imperativ stil

Imperativ

const output = [];

for (const number of numbers) {
    output.push(number * 2);
}

Deklarativ

const output = numbers.map(number => number * 2);

Imperativ kode beskriver ofte stegene. Deklarativ kode uttrykker i større grad resultatet eller transformasjonen. Den ene formen er ikke universelt bedre enn den andre.

Node.js

Del C · Broen videre

Dette trenger du før React

Før Modul 2 bør du kunne lese mønstrene under. Du trenger ikke kunne all JavaScript- eller TypeScript-syntaks utenat.

  • vanlige functions og arrow functions
  • objects, arrays og destructuring
  • import og export
  • map, filter og reduce
  • enkel TypeScript-typing og type inference
  • interfaces og union types
  • immutable datatransformasjoner
  • rollen til Node.js, package manager, Vite og ESLint

Målet er å lese koden, forstå dataflyten og kunne vurdere og feilsøke løsninger. Detaljsyntaks kan slås opp når prosjektet krever den.

Fra teori til arbeid

Hvorfor dette betyr noe i Prosjekt 1

Prosjekt 1 bruker webgrunnlaget sammen med TypeScript, Node.js, React, Git og testing. Teorien er et fundament for å forstå koden, evaluere KI-genererte forslag, feilsøke og diskutere egne og andres løsninger.

React erstatter ikke HTML/CSS-fundamentet: Komponentene produserer fortsatt et webgrensesnitt som må ha riktig struktur, styling, responsive behavior og accessibility.

Vanlige fallgruver

  1. Klikkbar divnår button er riktig element.
  2. Mange nested div-eruten semantisk struktur.
  3. Fast desktop-layoutmed mål som ikke fungerer på små skjermer.
  4. Grid uten layoutforståelsefor 2D Grid sammenlignet med 1D Flexbox.
  5. Responsivitet som bare krympingi stedet for å endre layout når det er nødvendig.
  6. ARIA som reparasjonnår et passende native element allerede finnes.
  7. Kopierte callbacksuten å forstå arrow functions og dataflyten gjennom funksjonen.
  8. Direkte mutasjonnår en array-metode kan produsere en ny verdi.

Rask repetisjon

Kortversjonen

  • HTML beskriver struktur og mening; CSS styrer presentasjon og layout.
  • JavaScript gir dynamisk oppførsel og er språket både browseren og Node.js kan kjøre.
  • Semantic HTML og native elementer er grunnlaget for accessibility.
  • Flexbox er primært endimensjonalt; Grid er todimensjonalt.
  • Viewport, media queries og breakpoints gjør layouten responsiv.
  • Dynamisk typing betyr at JavaScript-typen bestemmes ved runtime.
  • TypeScript legger statisk typekontroll oppå JavaScript og transpileres før kjøring.
  • Arrow functions brukes mye til callbacks, events og array-metoder.
  • Import/export deler prosjektet i gjenbrukbare moduler.
  • Interfaces og union types beskriver forventede data.
  • map/filter/reduce uttrykker vanlige datatransformasjoner.
  • Immutability betyr at nye verdier ofte produseres i stedet for å endre eksisterende data.
  • Tooling støtter kjøring, packages, build og statisk analyse.
  • Målet før React er å lese mønstrene og forstå dataflyten, ikke memorere all syntaks.
