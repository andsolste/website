1. Process: den viktigste abstraksjonen

En process er en instans av et program som kjører, med begrensede rettigheter. Et program er selve programfilen; en process er programmet mens det utføres. Flere prosesser kan kjøre samme program samtidig, for eksempel flere Chrome-prosesser.

En process har blant annet et address space, én eller flere threads og rettigheter til system calls, filer og andre ressurser. I denne delen av faget er utgangspunktet én thread per process.

Formulering å lære: «En process er OS-abstraksjonen for et program som kjører med begrensede rettigheter.»

2–5. Hvorfor isolasjon, modes og beskyttelse?

Programmer kan være buggy eller ondsinnede. Uten begrensninger kunne de lese andre prosessers minne, endre kernel-minne, styre maskinvare direkte, deaktivere interrupts eller ta over CPU-en. Operativsystemet må derfor isolere prosessene.

User mode brukes av vanlige programmer og har begrensede rettigheter. Kernel mode brukes av OS-kjernen og har full tilgang til maskinvare og minne.

En privileged instruction kan bare utføres i kernel mode, for eksempel endring av memory protection, direkte maskinvarekontroll eller deaktivering av interrupts. Forsøk fra user mode gir en exception, og kernel tar kontroll.

De tre sentrale maskinvaremekanismene er:

  1. Privileged instructions
  2. Memory protection
  3. Hardware timer
6–10. Memory protection og virtual memory

I modellen base + bound får en process et avgrenset fysisk minneområde. En adresse må oppfylle base ≤ address < base + bound; ellers oppstår en exception.

Modellen er enkel, men har problemer med voksende heap og stack, minnedeling, binding til fysiske adresser og fragmentering. Ledig minne kan være delt i små hull selv om total mengde er stor nok.

Virtual memory lar prosessen bruke virtuelle adresser. Maskinvaren oversetter dem til fysiske adresser ved hjelp av en translation table som kernel setter opp. To prosesser kan dermed bruke samme virtuelle adresse uten å bruke samme fysiske minne.

Et process address space består hovedsakelig av code, data, heap og stack. Heap vokser vanligvis oppover, mens stack vokser nedover. ASLR randomiserer plasseringen av blant annet stack, heap og code/data for å gjøre angrep mindre forutsigbare.

11–12. Hardware timer og trade-off

En hardware timer genererer periodiske interrupts, slik at kernel får kontroll tilbake selv når et user-program kjører en uendelig løkke. User code kan ikke deaktivere timeren.

Hyppige timer interrupts gir bedre responsivitet, men mer overhead. Sjeldnere interrupts gir mindre overhead, men dårligere responsivitet.

13–16. Mode transfer og system calls

Overgangen fra user mode til kernel mode skjer på tre måter:

TypeHva utløser den?Eksempel
InterruptMaskinvare trenger oppmerksomhetTimer, nettverkskort, disk
ExceptionEn uventet hendelse under kjøringDivide by zero, ulovlig minneaksess
System callProgrammet ber OS om hjelpwrite, open, exit

Et system call er et begrenset, kontrollert inngangspunkt til kernel. Når et program for eksempel åpner en fil, går det via bibliotekfunksjon og trap til kernel. Kernel finner argumentene, oversetter user-adresser, validerer argumenter og rettigheter, utfører operasjonen og returnerer resultatet til user mode.

Kernel går tilbake til user mode når et system call, en exception eller interrupt er håndtert, når et nytt program starter eller når scheduler bytter prosess.

17–18. Interrupt vector og kernel stack

En interrupt vector er en tabell som kobler en interrupt-type til riktig handler, for eksempel timer interrupt til en timer-handler eller divide by zero til en exception-handler.

Når en interrupt skjer, må CPU-en lagre program counter, stack pointer og processor state. Kernel bruker sin egen kernel/interrupt stack, fordi den ikke kan stole på user memory. State må kunne gjenopprettes før utførelsen returnerer.

20. Aktiv læring og eksamensforberedelse

Les Chapter 2.1–2.3 og slidesene først. Tegn så sammenhengen mellom process, user mode, memory protection og kernel mode. Test deg selv ved å forklare mekanismene høyt uten notater.

Prøv C-eksempelet nedenfor flere ganger for å se data-, stack- og heap-adresser, samt ASLR i praksis:

int staticVar = 0;

int main() {
    int stackVar = 0;
    int *heapVar = malloc(sizeof(int));

    printf("%p\\n", (void *)&staticVar);
    printf("%p\\n", (void *)&stackVar);
    printf("%p\\n", (void *)heapVar);
}

Viktigste muntlige forklaring: Et program i user mode kan ikke utføre privileged operations direkte. Det gjør et system call, CPU-en foretar en kontrollert mode transfer til kernel mode, kernel validerer og utfører operasjonen, og returnerer deretter kontrollen til user mode.
